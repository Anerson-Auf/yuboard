# Smoke test: identity, permissions и Canvas

Проверяйте в трёх разных browser profiles (например, обычное окно и два incognito/profile), иначе session cookie исказит результат.

1. Войдите system owner. Создайте два account-invite в админке и активируйте аккаунты `@viewer` и `@editor` в отдельных профилях.
2. System owner создаёт workspace и добавляет оба аккаунта через `Команда`.
3. Выдайте `@viewer` preset **Viewer**, `@editor` — **Editor**.
4. В профиле Viewer откройте доску: чтение карточек, вложений и схемы должно работать; создание, редактирование, перемещение и архивирование карточек должно вернуться с отказом.
5. В профиле Editor создайте карточку, откройте её, выберите `Схема` в sidebar, нарисуйте несколько линий и сохраните. Закройте и повторно откройте схему: рисунок должен остаться.
6. Откройте карточку в другом профиле: схема видна. Одновременно измените и сохраните схему в двух профилях: второй устаревший save должен показать conflict, не затерев первую версию.
7. System owner исключает `@editor` из workspace, пока тот держит доску открытой. При следующем realtime event профиль должен получить сообщение об отзыве доступа и вернуться на главную; загрузка доски должна быть запрещена.
8. В профиле `@editor` откройте `Сессии`, создайте вторую сессию в новом профиле, затем отзовите её. В отозванном профиле следующий API-запрос должен потребовать вход.
9. Заблокируйте `@viewer` в админке. Все его открытые профили должны немедленно потерять access после следующего запроса.

Зафиксируйте для каждого сбоя: шаг, аккаунт, browser, время и скриншот ошибки. Не тестируйте destructive delete workspace на единственном рабочем пространстве без backup.
